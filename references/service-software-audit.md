# Service and installed-software audit

Include this audit when WCB is invoked for PC slowdown, cleanup, startup reduction, or unnecessary/unused software review.

- Measure available RAM, disk free space, repeated CPU samples, and RAM grouped by application. Separate current resource contention from disk-space-only opportunities. Working-set totals may double-count shared memory; use system available RAM for overall pressure. A single CPU spike is not sustained load.
- Inventory running services with executable path, publisher/owning application, startup mode, PID, sampled CPU and RAM. Inspect dependencies and purpose before proposing a change. Include optional startup entries and relevant scheduled tasks. Do not classify a service as unnecessary merely because it is third party or automatic.
- Inventory classic applications from both machine uninstall registry views and the current-user view; include Store apps when supported. Avoid Win32_Product because querying it can trigger MSI repairs. Use Windows PowerShell for Appx cmdlets if PowerShell 7 cannot load the module. Record inventory gaps.
- Look for duplicate versions, overlapping tools, optional resident utilities and large applications. Verify separate install paths before calling entries duplicates; stale uninstall records can describe one shared installation. Multiple Python, SDK, runtime or build-tool versions may be dependencies.
- Check running processes, startup/service/task integration, user data and available usage evidence. Not running now, an old install date, missing launch history, or unavailable telemetry does not establish that software is unused. Label uncertain items as candidates and ask the user which they still use.
- Prioritize candidates by measured CPU/RAM and startup overhead. Distinguish expected benefit from observed benefit; uninstalling an idle application usually frees storage rather than CPU. Do not recommend registry cleaners or blanket service-disable lists.
- Preserve active chats/tasks, unsaved work, notes, playback, sync, remote-access sessions, networking/VPN/DNS, security, drivers and shared runtimes. Check for active jobs before touching their owning application. Prefer supported reversible startup changes when authorized.
- A request to check what can be uninstalled authorizes inspection and recommendations, not removal. Before uninstalling or disabling a service, present exact products/services, evidence, dependencies, user-data risk and rollback/reinstall route, and obtain authorization unless those exact actions were already explicitly approved. Use the registered/vendor uninstaller; never delete program folders or shared dependencies as a substitute.
- Back up registry values (key/name/kind/raw data), service startup/delayed-start configuration and task XML before an authorized change. Verify results and repeat comparable measurements; do not attribute unrelated fluctuations to cleanup. Keep reports local and omit secrets from command lines or configs.
